What's a timer?:
• A timer is a counter that receives a clock input either from an oscillator or an external clock.
• The speed of this clock is decided by pre-scalers picked by the programmer in the software.
• With each clock cycle the counter increments its value by 1
• counters could be up-counting, down-counting or up & down counting.
• each increment or decrement in a counter is called a tick.

-If one knows the clock pulse width size as well as the amount of ticks the counter did in total, one can determine how much time
has passed since the timer started counting.

How could you create a time delay using timer register?:
• By counting the number of ticks that occured since this counter started counting
• And since the clock pulse width is known by the input clock frequency and pre-scalers we can calculate the total delay time.


-Each timer has its own mode, these mods decide how the timer behaves, if it's upcounting or downcounting, if it does a specific
action on reset, if it triggers an external GPIO pin or not.

-In industry used MCU's there's timer peripherals with something that's called @cascaded_counters_mode, its basically the triggering
of another counter once it reaches its action triggering point. So it has multiple counters.
This mode is also called dependant mode.


What are the steps that should be considered when reading a timer:
1. The number of counters it has, timers could have multiple counters.
2. The value of F_clk for each counter and its pre-scaler.
3. Determine its mode: either independant or dependant.
4. In case of independant mode you need to decide if it's upcounting, downcounting or up & down counting
5. As well as its compare register and it's zero condition
6. Zero condition is the timer reseting itself back to zero when either a compare action or an overflow action is met
7. These actions are programmed by the user and could or could not fire an interrupt request as well.
8. It is possible that a timer could drive an external GPIO pin if programmed as so as well.

Case Study 1:
- You have a clock oscillator which consists of 24 MHZ and a prescaller of 12, we need to generate a 1ms delay knowing that the
  counter register has a 16-bit resolution.
• We calculate our input clock frequency by dividing the oscillator frequency by the prescaller: 24/12 = 2 MHZ
• We calculate the tick period by dividing 1 by the input clock frequency value: 1/2MHZ = 0.5 uS
• Since we need to reach 1ms delay we need to divide the total time by the single tick time to know how many ticks we need:
  (1*10^-3)/(0.5*10^-6) = 2000 ticks.
• once the counter reaches 2000 ticks it then resets to 0 and triggers an interrupt request that performs whatever action we need.

-You can control the duty cycle of a pwm pulse by using OCR0 register in an equation where 
Duty Cycle = ((255-OCR0)*2)/(255*2)
-Fast PWM mode only operates by the compare and overflow flags, you can control the duty cycle by changing the compare limit.

-What is input capture mode?:
• it's a mode that's used to measure the incoming PWM pulse timing, either T_high, T_low, T_total.
• Assuming there's an external pin tied to a timer and programmed to be input capture mode.
• when a clock signal is subjected to that pin and at the same time an event occured in the MCU, it records the last point from
. which it was counting and the count number at that point.

-What is PWM?:
• An array of pulses that happen periodically at a duty cycle.
• Used in DC motors in applications where speed control is desired.
• the average voltage between on time and off time amounts to the total speed output.

-What is real-time clock (RTC)? :
• This could be a module or IC that's purchasable or could exist within your MCU
• This clock contains a calender that keeps up with day, month, year timings.
• Works in low power mode (1V)
• Could contain a back up battery so that it stays active while the MCU is asleep or turned off.
• That's why some devices have a place for a small cylinderical lithium battery to maintain the RTC clock.
• An RTC IC module usually communicates with the MCU via I2C and has an external crystal oscillator.
• RTC has its own registers, some bits are responsible for controlling seconds, some for minutes and some even for years. 

-Is it possible to mimic an RTC operation using a normal timer peripheral?:
• Yes it is possible if you program the software to keep up with date and time for every time unit.
• However the RTC does all of that automatically because it has these calculations embedded in its hardware by digital designers.

-What are watchdog timers?: 
• A simple electronic device that's responsible for resetting the MCU for invalid software status.
• It's generally kept within loops and is executed periodically within that loop.
• If the watchdog timer is not called that means the loop is failed to execute and the watchdog timer resets the MCU.
• Most watchdog timers are normal timers with downcounting from the given value to 0
• Most MCU has its own internal watchdog timer within them.
• The watchdog timer interrupt has the HIGHEST PRIORITY below the exceptional interrupt.
• To use a watch dog timer in your code, you first have to initialize it with its timeout value e.g. wdt_init(timeout_cnt);
• And then include a reset funcion for that timer inside your main loop at the start or at the end of it.
• If the watchdog timer resets the MCU the program counter PC goes to the reset section in startup as if the MCU is rebooted.
• The watchdog timer is not used in personal projects or tests but in user products it is mandatory.
• Some watchdog timers in some MCU are more advanced and do not require a kick in order to reset, it monitors the code itself.
