**This lesson is very important as it tackles "interrupt", no interview has ever been made without asking about interrupts.

What is an Interrupt?:
• An interrupt is a signal "An interrupt request" generated by some event external to the CPU which causes the CPU to stop what it's
  doing and jump to a seperate piece of code designed by the programmer to deal with the event generated by the interrupt request.
• the interrupt functions are not callable by a line of code in C, instead they get called only when a certain hardware action is
  performed even though they exist in our code like any other.
• This is why the variables inside an interrupt function are of volatile type so as to prevent the compiler from removing any
  interrupt function that may not be called by the program.
• After an interrupt has been handled the program goes back to the line of code it was in the middle of executing.

What is an Interrupt Service Routine (ISR)?:
• For every interrupt there must be an interrupt service routine (ISR) or "Interrupt handler"
• when an interrupt occurs the microcontroller runs its respective ISR
• each interrupt has its own address depending on the MCU, each address can be known via the interrupt vector table found in TRM.
• All ISR's are declared as weak in the system startup code.
• The keyword "Weak" mans that another non-weak subroutine with the same name defined elsewhere can override this one. 

Explain an interrupt serviece routine operation where an internal interrupt from ADC gets handled:
• The pirephral ADC gets an interrupt signal through to the GIC interrupt handler.
• GIC and ADC both supposedly having their interrupt enabled through the register menu.
• GIC then sends an interrupt request to the CPU to inform it with the interrupt from ADC.
• The CPU sees that interrupt and sends an acknoledgement to the GIC to inform it to stop sending for this interrupt.
• the CPU then moves to the address coresponding to that interrupt specified by the vector table to resolve it.
• once the interrupt is resolved, the CPU continues from where it left off until it recieves another interrupt.

What's the purpose of a general interrupt controller (GIC)?:
• it containts all the registers for internal and external interrupts and handles them before going into the CPU
• Any interrupt action has to go through it first before it goes to the CPU.
• it can enable or disable recieving interrupts from any specific pirephral or external register.
• some interrupt controllers have registers that allow it to change interrupt priority and interrupt overhead.
• it pushes interrupts to the CPU through an organized system if multiple interrupts are fired at once.
• If an external interrupt occurs very quickly while the CPU is operating, the CPU might not detect it but the GIC will.


How to use an interrupt function?:
• first we must define all the interrupt vectors in the startup as weak aliases to the default handler function.
• this default handler funcion's purpose is to call main() or call another function that calls main().
• Next we can copy and paste the interrupt function's name from the startup into our main code and type the action to be performed.

-There are two ways a microcontroller serves interrupts, vectored arbitration system and non-vectored priority system.
What's the difference between vectored and non-vectored priority system?:
• Non-Vectored priority system does not have a vector for each interrupt, when an interrupt occurs the program counter jumps to
  one address, the CPU then checks each status registers of each address sequentially to determine which pirephral has caused
  this interrupt. This is an old method and is currently less popular as it is only used with MCU with less than 5 interrupts.
• Vectored arbitration system is the system we're used to, the MCU comes with a vector table reserved in its memory, each interrupt
  vector contains the address of that interrupt's ISR, when the compiler allocates program memory for interrupt handlers it places
  appropriate address for the ISR in the appropriate interrupt vector.


What is an interrupt vector table?:
-a list of interrupts contained within a MCU's program memory which contains interrupt related information such as interrupt
request number, interrupt request source, vector address.


What is a software interrupt?:
• A software interrupt otherwise known as an "exceptional interrupt" is a type of interrupt that doesn't happen through wires or
  connections to the GIC, but instead it happens when he CPU tries to interrupt itself. You will learn more about that later on.
• The ARM CMSIS library defines all system exceptions by using negative values.


What's the difference between polling and interrupts?:
• Polling is another invoking mechanism like interrupts The difference lies in the way the CPU checks for actions from the I/O devices
• In interrupts, the input from I/O device can arrive at any moment requesting the CPU to process it.
• In polling the CPU keeps asking the I/O devie whether it needs CPU processing and it won't know until it asks I/O device.
• Polling use in code resembles a constant check within a while loop's condition or an if statement inside of its body
  for example: 
  while (true)
  {
    if (PIND.2 == 0)
    //do something
  }
• Interrupts are more efficinet in CPU use as there is no constant order to check a condition, it also can be masked.
  for example:
  void main()
  {
    //do your common task
  }
  ISR() {//whenever PIND.2 is 0 then do something}
• Interrupts are hardware mechanist whereas polling is a protocol.
• Polling is prefered when the events happen at a rapid rate whereas interrupts are more efficient if they only happen occasionally.


When exactly does the CPU handle the interrupt request when it gets it?:
• When an interrupt request is issued while an instruction is being exectured, the CPU completes the execution of the current instruction.
• It then clears the interrupt status bit and stores the address of the next instruction that should have been executed on the stack.
• The interrupt vector of the triggered interrupt is then loaded in the program counter and the MCU starts executing until it reaches
  a "RETI" instruction (Return instruction).
• Once the "RETI" instruction is executed the stored address of the next instruction gets loaded onto the program counter.
• Normal operation now resumes as the MCU is back to where it was prior to the interrupt

What is interrupt latency?:
• It's the amount ot time taken by the processor from the time the interrupt request is issued to the time it starts processing at.
• An important aspect of kernel real-time performance is the ability to service an interrupt request within a specified time window.

What's the difference between sequential and nested interrupt processing?:
• Nested interrupt processing relies on interrupt priority order, even if the program was in the middle of executing an interrupt
  and an interrupt request of a higher priority gets issued the program stops operation and resolves the other interrupt first.
• Sequential interrupt processing relies on the order the interrupt requests were recieved by regardless of the priority order.

How to make the interrupt reach the CPU?:
• The most important two things regarding an interrupt is its status and its mask.
• Status is a read only pirephral that tells the CPU whether an interrupt occured or not.
• Mask is like & with the interrupt request, it could be 1 or 0, through it you can determine whether you want an interrupt or not.

What is an interrupt overload?:
-When external interrupts occur too frequently it causes other activities in the processor to be halted temporarily.
-To solve this issue there are 3 methods:
1. Making a strict software scheduler so that any interrupts that stack over the first pending one are discarded.
2. Making an interrupt counter that resolves interrupts up to a certain number, any further and they will be discarded.
3. Some hardware has an interrupt schedulate that can be used
